## D01–D03: continuity and history requirements

**Compaction:** preserve the full typed error, model/route, operation and request identity, retry/stop reason, effective window, estimate/floor, and real phase timing. Do not infer sensitive request content from a clipped log or print it indiscriminately. Distinguish summarizing, retrying, cancelled, failed, degraded, and successfully committed states. Retain user control during long attempts.

Review the mechanical fallback policy explicitly. Recommendation: a semantic-summary failure should leave the unmodified prompt view recoverable and expose retry/stop or an explicitly selected degraded continuation. Do not keep sending an oversized prompt indefinitely; failure and token-headroom handling must be designed together. The present continue-with-digest policy is existing behaviour, not a new choice endorsed by this plan. Keep automatic and manual compaction behaviour explicit. Preserve goals, plans, constraints, pending work, and retrieval anchors through repeated compaction; include prior summaries rather than progressively erasing their useful content.

Citations improve retrieval but do not make summarization lossless. Keep summary text distinct from authoritative event anchors; an instruction to append a fixed sentence does not prove the model obeyed it. NTI-006's current wall names summarization.rs while fallback lives in compaction.rs: amend the wall before implementing that requirement. Never follow an invented call id or silently substitute the nearest call.

**Diagnostics:** one terminal writer owns paint. Structured notices reference full error details; diagnostic-file/subscriber errors remain visible. Keep JSON-RPC stdout protocol-only, print-mode stderr useful, and terminal restoration correct. Suppressing warnings is not a repair. Escape terminal controls in displayed external content.

**Resumed history:** distinguish persisted history, the compacted provider prompt, and the frontend's loaded window. `app/session_replay.rs` already requests an initial page, and `app/transcript.rs` tracks cursors/has_older and asynchronous reads. The reported bug is not proof that there is no replay implementation or no stored history. Trace the actual resume invocation, source identity, initial tail, older-page requests, compaction visibility, body revisions, and scroll anchors. Native terminal scrollback is not the retained history owner.

Demand older pages when the user scrolls past the loaded boundary; avoid loading every raw result at startup. Show loading, oldest boundary, unavailable body and read failure distinctly. A page arriving late may not switch sessions, steal a selection, reset the draft, duplicate a turn, or force the view back to Latest. Compacted original events remain inspectable as historical content, not reinjected into the provider. Include very large results, multiple compactions, child histories, resize, and tool association across page boundaries in later acceptance.

**Resume identity and log recovery:** preserve exact ID/prefix behaviour; apply the settled project scope to name lookup and refuse ambiguity with candidate IDs. A session name still does not imply automatic resume. Fix replay-time `Utc::now()` substitution using persisted timestamps. Wall-clock timestamps can tie or move backward: preserve authoritative event ordering and use explicit tie-breakers rather than requiring strictly increasing wall time. Discover registered child timelines by their index entries; make descendant coverage and errors explicit. Rebuilding history must not respawn completed children.
