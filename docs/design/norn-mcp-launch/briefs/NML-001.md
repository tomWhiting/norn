## Requirements

### R1: Parse named runtime MCP documents without side effects

WHEN --mcp-config JSON|PATH is repeated, THE SYSTEM SHALL parse strict mcpServers objects into existing McpServerSettings, accepting the standard type field as an alias for transport. It SHALL reject invalid JSON, unknown fields, duplicate JSON keys and server names, unsupported settings, and collisions with --extension before any MCP subprocess starts. Inline raw JSON SHALL be redacted in Debug and errors. Relative document paths and server commands resolve from the effective --working-dir. No settings file is written.

**Acceptance:**
- Document root is exactly {mcpServers:{name:definition}}; empty maps are allowed, but wrong/unknown shape is refused.
- Repeated documents may contain disjoint names. Duplicate names in a document, across documents, and with URI extensions are refused; no silent last-write wins. Duplicate nested object keys are refused as well.
- Command,args,env,url,headers,enabled and existing limits remain typed by McpServerSettings and existing validate_settings; type/transport double declarations are refused.
- No shell interpretation of arguments, no secret values in parse errors or CLI Debug, no persistent writes, no arbitrary new limits.

### R2: One launch configuration for interactive, print and driven RPC

WHEN a launch resolves MCP sources, THE SYSTEM SHALL combine documents and existing named URI extensions in the CLI overlay, above existing disk layers, before channel-source resolution. It SHALL use the same resolved map for MCP control state and runtime startup, including CLI list/inspect and refresh. Driven mode remains one run: flags configure startup; no new run/execute parameters, dynamic RPC endpoints, daemon or permission relay.

**Acceptance:**
- Real norn process with inline JSON launches a Rust stdio fixture with exact args/env and exposes its tool to a local model stub.
- Same configuration plus --protocol jsonrpc completes initialize/run/execute and emits source-attributed channel input during the active run, with clean JSON-RPC stdout.
- An actual interactive launch resolves the same map (PTY smoke or public shared CLI assembly), including named wake policy.
- Bad configuration in driven mode returns an id-matched run/execute error and does not start a sentinel MCP server; normal startup exits2.
- CLI overlay wins over conflicting saved definition, can disable it, is preserved across reload, and leaves configuration files unchanged.
