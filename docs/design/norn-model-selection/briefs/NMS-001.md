### R2: Resolve against the actual backend before launch

WHEN a model is selected, THE SYSTEM SHALL resolve its canonical identity, selected provider/backend capabilities and explicit context override before arming or reservation. THE SYSTEM SHALL NOT borrow another backend's context or effort policy. The outbound Responses and compatible Chat boundaries SHALL validate typed effort before network access, and raw provider options SHALL NOT override owned effort/tier policy. Already-resolved startup model IDs SHALL NOT be expanded through aliases a second time.

**Acceptance:**
- Same model ID on two fixture backends uses only selected limits/efforts/tiers.
- Unknown model needs explicit context; supported aliases retain startup precedence.
- Derived window and explicit override are distinguished by provenance, not numeric equality.
- Children validate before reservation/persistence.
- Ultra parsing/help and CLI mapping work; unsupported Ultra refused on Luna/undeclared API route before request.
- Existing stale metadata tests are updated to the supplied facts, without importing unmerged branches.
- CLI alias work -> local-v1 with another alias local-v1 -> local-v2 starts local-v1 and live /model work also selects local-v1. Literal targets retain their identity even when an alias key shares the spelling.
- Compatible Chat refuses undeclared typed efforts and raw reasoning_effort/service_tier overrides before request dispatch; ordinary unrelated provider options remain usable.
- Real CLI assembly on Responses and compatible Chat admits spawn/fork for the same model/route using the operator-explicit root context. Explicit child policy wins; different-model or different-route children never borrow it; live model publication and descendants preserve its provenance. Missing metadata refusals name the route, not a guessed typo.
- Raw reasoning.effort and service_tier cannot override typed policy through top-level, openai or openai_responses provider option scopes on either Responses backend; unrelated options remain usable.
- Missing metadata and unsupported declared capabilities have distinct source-aware diagnostics. CLI startup refusals use argument exit 2, one norn prefix and empty stdout.
- An operator alias targeting a bundled alias resolves once to its canonical identity; user-alias chains are not followed. Whitespace model identities are refused even with an explicit window.

### R3: Publish one validated model transition before the next turn

WHEN the user switches models, THE SYSTEM SHALL prepare and validate the complete destination state before atomically publishing model, effective context, tool-output budget, effort, tier and display under the driver owner. IF validation fails, THE SYSTEM SHALL preserve every previous value. A switch SHALL NOT replace provider/history behind the user.

**Acceptance:**
- Sol→Spark→Astra derived limits change before the next turn.
- An explicit override equal to the original default remains explicit and rejects incompatible destination.
- Failed switches retain context, ToolOutputBudget, model, effort/tier and display.
- Startup and live aliases share precedence; aliases needing another provider/profile fail unchanged.
- No unwrap/expect/suppression/ignored tests added; new modules stay below500productionlines.
- The promised crates/norn-tui/tests/model_selection.rs drives the public TUI through real /model, /effort and /service-tier dispatch, asserting next-turn model/budgets and atomic refusal; inline helper tests do not substitute for this path.
- The builder binds the effective compaction reserve used by the stable prompt. A live switch preserves that exact reserve and refuses atomically if the destination window would enable or disable automatic compaction; compatible transitions still succeed. CLI and real TUI dispatch exercise the refusal.
- Print-mode orchestration remains below 500 production lines after shared model publication; existing failure reporting and pre-assembly error-envelope handling live in print/error.rs with identical messages, exit codes and envelope behavior.
