# Norn-Retained-Tui — User Stories

## Session participant — human operator or observing model

**S1.** As a session participant I can distinguish committed, provisional and incomplete history, and inspect the exact recorded body without affecting execution.

**S2.** As a participant I can keep reading a compact conversation and exact call changes while the terminal resizes and work continues.

**S3.** As a keyboard or mouse reader I can find, select, copy and export content and retain all current controls, with real terminal proof.

**S4.** As a session participant I see each accepted human prompt and assistant response once, can inspect every exact execution/completion fact, and see uncertainty or errors without duplicated rows or guessed associations.

**S5.** As a participant I can read every line of a user message in the same intended style and interact with a stable retained terminal display, without changing the familiar layout.

**S6.** As a participant I can see the existing main/fork/subagent status tree while work proceeds without losing composer width. Selecting a target conversation and messaging it remains a separately tracked requirement until implemented.

**S7.** As a participant I can select the main session, a fork or a subagent, read its actual conversation and send to that exact target with an acknowledged result. This remains pending beyond passive status restoration.

**S8.** As a participant I can use /pane to toggle the side area and /pane diff or /pane agents to select its actual content. Existing /view commands remain supported. Remembering the new content choice and selecting/viewing/messaging individual agents are explicitly tracked until implemented.
