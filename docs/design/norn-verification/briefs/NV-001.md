### R7: Guard every Norn venue leg against persistent dirty source

THE SYSTEM SHALL run every gates.json command through scripts/source-bound-leg.py. Before executing the command it SHALL require a clean tracked/index/non-ignored untracked tree and capture HEAD, then require the same HEAD and a clean tree afterward. Git probe failures SHALL refuse the leg. Command failure SHALL remain nonzero even if postchecks also fail. The guard SHALL record declaration and guard SHA256 witnesses. This subject-owned mitigation SHALL NOT claim immutable execution or closure of Aion X.1: edit-execute-restore inside a leg and replacement of the declaration/guard by an unreviewed writer remain outside the pre/post guarantee. Each witness SHALL compare every tracked working-tree blob directly with its HEAD tree object identity using the repository object format, including symlink targets and executable mode, without trusting Git stat-cache cleanliness. Unsupported tracked entry types SHALL refuse.

**Acceptance:**
- Real committed temporary Git fixtures prove clean execution, tracked/index/untracked refusal before execution, ignored build-output acceptance, moved HEAD refusal, post-execution dirtiness refusal, Git failure refusal and command exit propagation.
- A change restored inside the command is explicitly tested as a documented limitation, not reported as immutable execution.
- Every declared leg invokes the guard; diagnostic-runner runs all declared Python regression suites with first-failure propagation. R8 adds a compile-only live target leg while preserving this requirement.
- Guard logs name HEAD, declaration SHA256, guard SHA256, command exit and any failed probe; landing review compares digests with the exact reviewed commit.
- No Cargo/build/service operations occur in these fixture tests; no invented timeouts, waivers or source cleanup.
- A same-length source edit with restored mtime and a clean Git status is still refused by direct blob identity; mode changes with core.fileMode disabled and symlink-target changes are refused. Blob/filter normalization is not silently accepted: this guard requires the checked-out bytes to match committed blobs.
