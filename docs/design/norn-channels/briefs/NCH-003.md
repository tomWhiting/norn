## Requirements

### R1: Explicit named opt-in, policy and retained quotas

WHEN channels are requested, the CLI SHALL require an exact configured source name and a policy supported by the actual CLI mode under R4, positive retained-message and retained-byte quotas, and explicit RejectNew overflow. Missing, zero, duplicate, unknown, disabled or non-stdio source configuration SHALL fail before provider or MCP connection. Ordinary MCP tool activation SHALL NOT enable channel input. Shared-project approval SHALL remain independently required. No numeric or behavioral default is added.

**Acceptance:**
- The real CLI parse/resolution path accepts explicit Wake and NextTurn selectors subject to R4, refuses Hold by name until CLI release/deny controls exist, and rejects missing required quota/overflow fields, zero values, duplicate sources and malformed policy selectors.
- Named configuration resolution refuses missing, disabled and HTTP sources without connecting anything; approved shared-project handling remains the runtime owner responsibility.
- CLI launch without channel arguments retains ordinary MCP behavior and does not allocate an inbox.

The driver SHALL await explicit initial runtime activation before the first turn, with staged messages published only with the committed generation. The shared print assembly also covers driven mode. Configuration, initialization and connection failures SHALL remain visible with their referents.

**Acceptance:**
- Print/driven and TUI drivers install explicit channel configuration through the library root assembly and await initial activation; they do not preallocate an unrelated recipient UUID.
- Startup diagnostics show each requested source, its policy, effective limits, overflow and runtime/approval outcome without message content.
- Model-selection remediation in overlapping driver/resolve files is preserved during integration; no loop owner, delivery or tool-generation file is edited under this brief.
- Initial tool definitions and introspection are refreshed from one committed runtime/generation pair. Startup unmatched-name diagnostics include only published executable generation names alongside the original registry; configured or disabled source names never imply a match.

### R4: Refuse policies without a consumer in the actual CLI mode

WHEN channels are requested, the first CLI release SHALL accept Wake and NextTurn in the interactive TUI, and Wake only in plain print or driven JSON-RPC. It SHALL refuse Hold until CLI inbox release/deny controls exist. Validation SHALL use the actual driver mode, including pipes and terminal-capability fallback; an explicit jsonrpc protocol SHALL always count as one-shot. Unsupported policies SHALL fail with the source, policy and unsupported-mode reason before reading stdin, accepting a driven run, constructing a provider or launching MCP servers. The process SHALL exit 2 with stderr diagnostics and empty stdout. Wake in a one-shot invocation SHALL join its active run only and SHALL NOT extend the process lifetime. The library Hold/NextTurn/Wake APIs and the driven one-shot protocol SHALL remain unchanged.

**Acceptance:**
- Pure validation covers both actual modes, explicit JSON-RPC overriding the supplied TUI mode, no channel arguments, defensive Hold refusal and each supported combination. It does not infer the mode from cli.print.
- Real norn binary tests cover explicit print, pipe-selected print without --print, and driven JSON-RPC with no run frame. Unsupported NextTurn and Hold produce exit 2, empty stdout and named source/policy/mode diagnostics; a configured marker MCP source never starts.
- CLI help advertises NextTurn for interactive TUI only and states that Wake in print/driven is limited to the active run; Hold is not offered as an available CLI policy.
- TUI validation runs before provider startup and revalidates as print after terminal fallback. Existing positive TUI delivery fixtures and library Hold release/deny tests remain valid.
- Print orchestration remains within 500 production lines; this row does not add a daemon, persistent inbox, second driven run, policy coercion, quota default or linger setting.
