## Requirements

### R1: Idle wake without polling or operator-prompt conversion

WHEN the installed session owner reports published Wake input while the TUI is idle, the terminal event loop SHALL wake through a dedicated push future and start the ordinary external-message turn path without creating or slash-parsing a user prompt. The session owner SHALL perform framed persistence and retained quota release. Hold and NextTurn input alone SHALL NOT wake this idle path. The existing turn-local cancellation, rendering, follow-up prompts and pending child results SHALL remain available. A closed or failed wake owner SHALL return a named typed TUI error rather than spinning or silently falling back. WHEN a channel-triggered turn is interrupted, fails, or stops before completion, the TUI SHALL pause automatic channel wake, preserve retained input and display the reason. The next ordinary operator turn SHALL rearm automatic channel wake; an operator follow-up submitted during that channel turn also rearms it. This state SHALL belong to the TUI event loop and SHALL NOT create a retry timer or drop the inbox.

**Acceptance:**
- The channel wake select arm is separate from the RENDER_TICK arm. A session without channels waits without a new timer or task.
- The turn starts from a typed channel wake seed; its first request and event history contain the escaped source frame exactly once, with no fabricated empty UserMessage.
- An external payload beginning with /model or /quit remains external content and does not dispatch a host command.
- Existing composer text is preserved while the idle channel turn runs. Follow-up handling, root cancellation ownership and ordinary turns reuse the established run_turn lifecycle.
- Hold and NextTurn retain their existing owner policy: only Wake makes the idle readiness future resolve.
- A distinct typed McpChannelDeliveryEvent emitted after persistence renders source and raw external content as an external-channel transcript row, preserving the existing composer. Rendering neutralizes terminal control sequences; the event refers to the exact persisted framed UserMessage and never pretends to be operator keystrokes or an agent sender.
- A channel wake rejected before persistence does not auto-loop. The terminal stays interactive, retained input remains charged, the pause reason is visible, and a new ordinary operator turn can persist that input exactly once and rearm later autonomous Wake input. Ctrl+C retains its existing turn-local cancellation token.

A protocol-clean Rust custom test harness SHALL launch itself as both a stdio MCP fixture and a real run_app process in a pseudo-terminal. Test synchronization SHALL use protocol messages and an owned loopback connection, never filesystem or render-timer polling. The fixture SHALL prove a push arriving after the interactive UI is idle causes a provider call and exact persisted channel event. Test deadlines are hang diagnostics only.

**Acceptance:**
- An ordinary cargo test workspace run executes named real-TUI channel scenarios and returns nonzero on failure. MCP subprocess mode writes only JSON-RPC data to stdout.
- The parent waits for the actual terminal input panel, then commands the Rust source to emit; provider capture proves that push initiates the request without typing Enter.
- A channel payload resembling a slash command reaches the provider as an escaped frame and preserves model/session identity and any existing composer draft.
