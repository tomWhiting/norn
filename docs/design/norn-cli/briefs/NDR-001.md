# NDR-001 — persistent driven conversation

Status: implemented; local verification recorded below. Fable review and the
exact-commit 205 battery remain outstanding. No landing claim.
Owner request: Waffles, relayed by Ripley on 9 September 2026, Melbourne time:
repeated `run/execute` requests must use one open Norn process and runtime.

## Requirements

1. R1: Keep one assembled agent, provider, MCP runtime and in-memory session
   across sequential requests. No subprocess per utterance or session replay.
2. R2: One input owner handles complete newline-delimited requests; an active
   run rejects overlapping execution. Partial input survives run boundaries.
3. R3: Stream events before the matching terminal result. `initialize` works
   idle and active. EOF ends the conversation after the accepted run finishes.
4. R4: Preserve inject/steer semantics. Cancellation ends the current run;
   a later run gets a fresh token without reviving cancelled descendants.
5. R5: Keep model/schema/slash state, history and session identity between runs.
   Expose the persistent lifecycle in capabilities; document session shutdown.
6. R6: Malformed frames and invalid-state requests are answered explicitly.
   Transport failures cannot masquerade as clean completion.
7. R7: Explicit session rotation (`/clear`) closes the connection with a typed
   receipt naming the replacement session. This deliberately avoids retaining
   stale action-log, fork, cache or provider bindings. Parent approval on
   9 September 2026: close-on-clear is an explicit rotation, not restart per
   utterance. The TUI precedent is `app/rotation.rs`; full live rebinding is
   outside this delivery.
8. R8: Preserve existing one-shot result followed by EOF unless `initialize`
   explicitly selects `runLifecycle: "persistent"`. Advertise both choices
   and the selected lifecycle. Freeze that selection after the first accepted
   run. Waffles's 9 September 2026, 14:06 Melbourne ruling supersedes the
   initial default-persistent design to preserve Aion adapter compatibility.
9. R9: Own signal handling for the entire connection, including idle periods
   between requests. Interrupting an idle connection must terminate it.

## Acceptance

Focused tests must demonstrate two requests with distinct results and one
runtime/session, cancellation followed by a successful run, live steering,
busy rejection, EOF, failed transport, partial frames across completion, and
event/result ordering. Strict workspace Clippy and formatting are required
before commit. The exact-commit 205 battery is separate from local checks.
