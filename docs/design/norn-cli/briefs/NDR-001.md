## Purpose

Waffles, relayed by Ripley on 9 September 2026 Melbourne time, requires repeated voice-driver run/execute requests on one open Norn process and runtime. His 14:06 ruling requires explicit initialize params runLifecycle=persistent; omission preserves one-shot EOF for existing Aion consumers. The normative design is docs/design/norn-cli/DRIVEN-PROTOCOL.md. Existing checklist/story references below describe the session, streaming, slash and cancellation responsibilities extended to driven mode; they do not declare the older NC briefs reverified.

## Task

Retain one assembled runtime behind a single input owner, negotiate lifecycle before the first run, preserve event and intervention contracts, and replace per-run cancellation tokens without reviving cancelled descendants. Publish typed close-on-clear receipts. The initial implementation is commit 5ccfcd2ce1293907fa0ac0862c524192bb4a4bc5. Waffles reviewed that commit with changes requested in Meridian message 2468081e-6098-4b94-a4db-1c738d1a7ad6 (9 September 2026, 14:50 Melbourne); the source correction and exact checked commit are recorded in docs/design/norn-cli/proofs/NDR-001-local.json. This brief records local implementation and review corrections, not a 205 landing receipt.

### R6: Report malformed input and transport failure

WHEN a frame, parameter or intervention state is invalid, THE SYSTEM SHALL publish an explicit protocol error. WHEN input or output transport fails, THE SYSTEM SHALL return an error rather than report clean completion and SHALL cancel a bound active run. IF execution and input shutdown both fail, THE SYSTEM SHALL retain the original failure and classification while attaching the shutdown failure. WHILE the session is open, THE SYSTEM SHALL supervise the output writer concurrently; a failed writer SHALL cancel active work or wake idle admission and await owned cleanup even if stdin remains open.

**Acceptance:**
- Actor tests cover invalid frames, parameters, unknown methods, closed queues and input failure
- Driven emitter tests cover writer failure and event loss
- failed_writer_wakes_an_idle_session_with_stdin_still_open injects writer failure after initialize without a model and verifies owned input cleanup

### R7: Close explicitly on session rotation

WHEN clear rotates a persistent session, THE SYSTEM SHALL return the replacement session_id and connection state closing with reason session_rotated, then close. THE SYSTEM SHALL NOT continue using old action-log, fork, cache or provider bindings. THE SYSTEM SHALL also print the existing cleared-session operator line on stderr before the persistent close receipt.

### R8: Negotiate persistence explicitly

UNLESS initialize explicitly selects runLifecycle persistent, THE SYSTEM SHALL return one terminal response and stdout EOF without waiting for stdin EOF. THE SYSTEM SHALL advertise one_shot and persistent choices and the selected lifecycle. AFTER the first accepted run, THE SYSTEM SHALL refuse lifecycle changes. Parameterless initialize SHALL preserve the current selection. WHEN the lifecycle is one_shot and execution is busy, THE SYSTEM SHALL preserve the original -32000 error text byte-for-byte.
