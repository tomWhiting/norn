# NTI-007: norn init conventions stops advertising enforcement the loader strips

> **Cluster:** norn-tools

## Purpose

Main's own CONVENTIONS.toml was cured at ff30f70: dead [rust.diagnostics]/[rust.remediation] declarations removed, header trued to the non-executing trust boundary, advisory triggers trued to what the stop hook actually reads. But `norn init conventions` still writes the disease into every NEW repo it initializes. The bundled chiron templates carry [LANG.diagnostics] tables (rust.toml declares clippy), the generator's flat_activations derives per-rule activations from those tables' keys, a PATH probe ADDS more diagnostics tables for tools it finds installed, and detected LSP support emits [rule.lsp.diagnostics] blocks. Norn's loader (load_non_executing_conventions) strips every one of those tables at load and accepts the orphaned activations silently — lookup_tool returns None, is_non_executing treats None as clean — so the generated file loads fine and the clippy/rustfmt/mypy/eslint activation lines sit there inert while reading as enforcement. That is the exact advertises-what-cannot-run class the review cured on main, still being emitted at the source. A fresh repo should receive a file that is true on day one: what it declares is exactly what runs.

## Task

Change the generator so its output is a fixed point of the sanitizer: emit only the tables and activations norn's non-executing loader keeps, derive activation handling and triggers from the template patterns' own declared handling, true the generated header to the trust boundary, and flip the existing tests that pin the defective output. Net deletion: the PATH-probe augmentation machinery goes away entirely.

## Requirements

### R1: Generated language definitions carry no process authority

The generator SHALL emit language definitions containing only tables norn's loader keeps after strip_process_authority (patterns and scalar configuration), and SHALL NOT emit diagnostics, remediation, lsp, or reports tables for any language. The PATH-probe augmentation (path_augmented_diagnostics, augment_template_with_diagnostics, and the probe parameter threading) SHALL be deleted, not gated or flagged — its only product is tables the loader strips. Template pattern definitions SHALL survive into the output verbatim.

**Acceptance:**
- Generated output for a project detecting rust, typescript, and python contains no [LANG.diagnostics], [LANG.remediation], [LANG.lsp], or [LANG.reports] table for any language
- path_augmented_diagnostics and augment_template_with_diagnostics no longer exist; no probe reaches the generation path
- Every pattern in the pinned bundled template appears verbatim in the generated language definitions

**Files:**
- modify: crates/norn-cli/src/commands/init/conventions.rs

### R2: Activations name only tools that exist after sanitization

Rule activation generation SHALL derive activations exclusively from the template's pattern keys, never from diagnostics, remediation, lsp, or reports keys. Each activation's handling SHALL mirror the pattern definition's own declared handling (PatternDef.handling is a required field at the pinned chiron rev 25161bc — this is source-derived, not invented). Each activation's trigger set SHALL follow the landed stop-hook asymmetry: handling block gets on = "tool|stop"; handling advise gets on = "tool", because the stop hook reads blocking outcomes only and a stop trigger on an advisory is dead configuration advertised as enforcement.

**Acceptance:**
- No generated activation names a tool from a diagnostics, remediation, lsp, or reports table
- A test pins the exact generated activation set for rust against the pinned template's pattern keys
- A test pins the trigger/handling pairing: block patterns produce on = "tool|stop", advise patterns produce on = "tool" — exercised against both handlings even though the current templates declare only advise, so a future template change cannot silently regress the asymmetry

**Files:**
- modify: crates/norn-cli/src/commands/init/conventions.rs

### R3: The generated header states the trust boundary

The generated header SHALL state what is true of norn's consumer: pattern checks and LOC limits run in-process; norn never executes subprocess tools; diagnostics, remediation, lsp, and reports tables are stripped at load; advisory findings fire at tool time only while the stop trigger acts on blocking findings alone. The hand-cured CONVENTIONS.toml landed at ff30f70 is the reference shape for this truth. The header SHALL NOT claim or imply that any subprocess tool runs after mutations.

**Acceptance:**
- The header names the non-executing boundary, the strip-at-load behaviour, and the advisory-vs-block stop asymmetry
- The header contains no claim that clippy, rustfmt, or any other subprocess tool executes
- A test pins the presence of the boundary statement in rendered output

**Files:**
- modify: crates/norn-cli/src/commands/init/conventions.rs

### R4: Generation is a fixed point of the sanitizer

The generated file SHALL parse to the identical structure before and after strip_process_authority — the sanitizer removes nothing, proving at the strongest available boundary that the file advertises only what survives. A test SHALL round-trip the generated file through norn's real loader path semantics (strip, parse, is_non_executing) rather than only through ConventionsConfig::load. The existing tests that pin the defective output — clippy/rustfmt activation assertions in generation_emits_only_detected_languages_with_correct_defaults and generated_file_round_trips_through_loader — SHALL be flipped to pin the trued output, red-first: each flipped assertion observed failing against the old generator before the fix lands.

**Acceptance:**
- A fixed-point test asserts parse(strip(generated)) equals parse(generated) structurally
- A loader round-trip test proves the generated file loads with is_non_executing true and zero stripped content
- The flipped pins were observed red against the unmodified generator before the fix (evidence in the lane record)

**Files:**
- modify: crates/norn-cli/src/commands/init/conventions.rs

## Boundaries

- SHALL NOT modify the chiron language_packs templates or move the dependency pin — the templates serve executing consumers correctly; the truing happens at norn's emission boundary
- SHALL NOT touch load_non_executing_conventions, strip_process_authority, or is_non_executing — the loader is correct; the generator conforms to it
- SHALL NOT keep the old emission behind a flag, config, or commented-out output — no backwards compatibility during this build; replace
- SHALL NOT invent handlings, triggers, or thresholds — handling derives from PatternDef.handling at the pin; trigger sets derive from the landed stop-hook asymmetry
- SHALL NOT push conventions.rs over the 500-LOC law — the change is net deletion; if new test volume crowds the file, split tests into a sibling module rather than bypassing the law

## Verification

- cargo clippy --workspace --all-targets -- -D warnings produces zero warnings
- cargo fmt --check passes
- cargo test -p norn-cli passes
- Red-first evidence recorded for every flipped pin
- A generated file dropped into a scratch workspace loads through norn's diagnostics_check without the loader stripping anything
